# DSH Desktop 兼容说明（本地适配完成，尚未发布）

当前工作区增加 DSH Desktop 0.2.0-rc.2 适配。npm 已发布的 Top100 1.3.13 只完成 Web 实机验收，不能把本页作为其桌面兼容承诺。

## 适配行为

- 从宿主 `profileContext` 读取正在运行的 `desktop` 配置目录、DSH 安装位置和内置包管理器。桌面中不使用 Top100 旧的 `profile: web` 配置，也不依赖启动参数推测目录。
- 作者安装示例中的标准 `--profile web` 可在桌面提取安装源，实际安装仍绑定当前 `desktop` 目录；自定义 Profile 和私有 registry 限制保持不变。出现安装按钮不代表已确认目标插件的全部桌面功能，安装前仍检查包身份、版本与补丁。
- 桌面壳转发请求时会移除 `Origin`；桌面接口通过宿主 `connection.admit` 校验来源与登录 Cookie，未通过鉴权的读写均拒绝。普通 Web 保留原有同源写入检查。
- 安装、更新、卸载与失败恢复调用当前 DSH 的官方包管理操作，使用相同的 Profile 写锁、版本兼容检查及进程取消机制。不要求另装全局 Node、pnpm 或 dsh；宿主未提供内置包管理器时明确报错。
- 安装前后使用官方 Profile 加载和补丁组合接口检查配置，支持宿主内置 Bundle 和多文件补丁。
- 安装确认能识别桌面宿主的 DSH 版本；诊断从宿主实际安装位置查找官方依赖。
- 保留现有 Web 和旧桌面接口。桌面需要重启时提示退出并重新打开应用，不通过 Web 的进程接管按钮重启 Electron。

## 本地验收包的安装

先打开 DSH Desktop 一次以初始化环境，随后完全退出。在桌面菜单的“管理 dsh 命令”中安装官方命令后，使用该命令将验收包安装到桌面 Profile：

```sh
dsh plugin --profile desktop add /absolute/path/to/verified-top100-package.tgz
```

将路径替换为实际验收包，再重新打开桌面应用。安装到 `--profile web` 的插件不会自动成为桌面插件。不要手动搬动 Web Profile、覆盖补丁或复制模型密钥。

新版本尚未发布，请勿直接将 `npm latest` 视为本页所述候选版。正式版本号、可用平台与实机验证范围以发布说明为准。

## 验收范围

自动化回归覆盖官方桌面目录绑定、内置包管理器选择、输出、失败与超时、取消、销毁期间的异步加载、Profile 校验及桌面版本识别；旧版 Web 路径继续保留。

2026-09-30 本地验收通过 63 个测试文件、942 项测试及 8 项安装包检查。使用官方 0.2.0-rc.2 运行依赖与对应桌面宿主源码，在隔离桌面 Profile 完成候选包加载、测试插件安装与升级、启停、卸载、宿主重启，以及官方 `dsh-app://` 转发函数的鉴权检查。旧 Web 0.1.5-rc.3 的加载、同端口重启和诊断回归通过。

随后在官方签名的 macOS ARM64 Electron 0.2.0-rc.2 应用中完成候选包安装、重启、榜单和已安装页面加载；修复桌面安装源识别后，回归增至 945 项测试。诊断为零错误、零警告；Top100 自身已确认运行，但宿主内置 `dsh-base` 的运行状态未确认，界面如实显示该信息。

最新一轮回归仍为 945 项插件测试通过，另有 108 项网站测试通过。在官方 macOS 安装包自带的 Electron 44.0.0 / Node 24.18.1 中，使用 ASAR 内官方模块及自带 pnpm，对隔离 Profile 完成实际安装、升级、卸载和配置校验；原生界面的搜索、分类、排序、Skill 安装预检与取消、已安装刷新及诊断也已检查。未逐个安装第三方项目，Skill 实际复制与回滚仍以自动化测试为证据。

隔离运行验收不使用日常 Profile，不继承模型凭证，不发起模型请求。原生应用验证未发送模型消息；Windows 与 Linux 尚未实机验证。原生启动与页面检查不替代全部第三方插件的兼容性验证。
