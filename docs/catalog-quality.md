# 目录质量与来源状态

> 付费模型默认关闭。当前日常维护已获准在 `daily-source-changes` 范围内处理新增或功能资料变化的条目，并分别启用热榜/新锐各前 100 与 Skills 前 100 的可靠中文缺口处理；不包含榜外存量、长尾整批或全库重新分类。真实请求仍须具备启用开关、密钥、获准范围和有效价格/金额配置，全部入口共用持久化预算账本，使用 Flash、显式非思考、日 5 元/月 50 元与批次上限。独立批次需要精确请求名单和另行确认。默认关闭、已授权日常范围与暂停的长尾任务应分别判断；实现与限制见 [model-budget.md](./model-budget.md)，离线测试不证明未来输出质量或供应商账户总费用。

此规则用于采集、SQLite 同步、官网和 DSH 插件的目录展示。它区分发现线索、结构证据与安装来源预检；预检通过不代表已安装、宿主兼容或功能运行通过。

## 收录与历史记录

- 鉴权搜索可能返回私有仓库。元数据明确为私有时，采集在读取文件和复用检测缓存前排除；历史项目经元数据刷新确认转为私有时也不恢复。公开拒绝报告只保留匿名原因，不能包含这些项目的名称或描述。
- 名称、Topics、README 中提到 DSH 只作为候选发现线索。Bundle 需要有效声明及对应 patch 文件；Client 需要平台与客户端导出；Host 需要运行时依赖与入口。仅有开发依赖、关键词或 CLI/Desktop 标识不能替代插件结构证据。
- 结构采集默认并发 10；`DSH_COLLECTION_CONCURRENCY` 可设置 1–50，越界立即拒绝。GitHub 来源查询继续使用各自限速，并发增大不会改变来源配额或完成状态。
- 常规采集只需要一仓库一个主对象：优先确认根包，再按既定顺序检查子包，均未找到时才回退到技能。确认首个有效主对象后停止无关目录读取；独立完整探测模式仍可枚举多个包或技能，主对象选择顺序保持一致。
- Discovery policy 为 6。缓存复用同时核对策略版本、安装解析器版本、仓库推送时间与原检查时间。
- 文档缓存 policy 为 2。README 与 SKILL.md 的缓存绑定仓库、所选路径、推送时间和分支；检测缓存也检查文档策略版本。只有真实 404 视为缺少文档，限流、服务错误和读取超时进入待复核，不写入成功检测缓存。
- 发现来源中途失败时保留已取得的候选，并将该来源标为不完整，继续其他独立来源。代码搜索窗口、npm 页数上限和仓库分页不足均保留在来源审计中，不能将本轮执行结束视为全网覆盖完成。
- 支持 `pnpm-workspace.yaml` 声明的子包和 `packages/*/*` 两层目录模式；限制目录探测预算，无法读取或解析已发现的 workspace 时保留为未确认，不据此判定仓库没有插件。
- 子包或技能目录超过扫描预算时，已确认的插件或技能仍可收录；若已检查部分没有结果，则标记待复核，不把未检查的剩余目录当作无效而删除旧条目。
- 本轮明确拒绝的仓库不再从旧目录自动补回。因网络等原因暂时无法确认的历史条目保留原检查时间，标为“收录依据待复核”；插件端归入生态项目，不作为已确认插件推荐。
- `data/discovery-review.json` 保存完整的拒绝与待复核记录。本次内容修订不证明全库仓库结构均已重新核验；全量采集不是本地预览或定向内容修复上线的前置条件。

## 分类与中文简介

- 分类按主要功能选择，模型只生成一个主类；固定复核有独立功能证据时可保留多个类别，最多三个。不因“插件市场”分到知识、不因使用模型分到 Agent 增强、不因存在 UI 分到外观。
- 固定分类保存在 `collector/config/reviewed-categories.json`，中文简介保存在 `collector/config/reviewed-descriptions.json`。固定复核内容绑定原 description、README 摘要、条目类型与所选包名/路径，资料或身份变化后停止套用。旧的未绑定记录不能套用到已有安装包或子目录的条目。
- 代码中的 `manual` 表示固定覆盖规则。本次规则由 AI 阅读资料后逐条核对形成，不表示用户或同事已经真人验收。
- 固定复核发现已发布介绍不属于当前包时，可对精确来源设置 `suspended: true`，显示待生成并清空相应固定分类；每日队列、批处理、内容合并和展示共用撤回结果，旧的完成缓存不能恢复已撤回内容。来源或包身份变化后不继续套用这条撤回规则。
- 分类 policy 为 4，缓存绑定策略版本和原始资料与收录包名/路径的哈希。旧策略分类不继续冒充固定复核或模型确认结果。证据不足时使用保守候选分类或暂不分类；因此迁移后长尾分类数量会减少。
- 模型分类置信度至少 0.75。原 description、README 的明确功能用于兜底，名称、Topics 和生成标签不单独决定分类。
- 展示端共用中文质量检查；品牌名和技术名允许保留英文。无有效中文简介时显示“中文简介待生成。”与相应来源/处理状态；只有满足资料、范围、尝试次数及预算门禁的作业才进入付费队列，不以英文或通用空话冒充已完成翻译。
- 新生成简介建议 30–60 个汉字，英文产品名保留，总长最多 160 个字符；不足以说明具体用途时继续待补齐。
- 固定复核与有来源的模型历史可按服务端规则保留旧简介并标注真实核验或生成日期及待更新状态。旧文可展示不等于当前来源已复核，也不解除分类、模型作业或预算保护；身份变化、明确撤回和已知错误仍隐藏。细节见 [日常运维的来源与历史处理](./daily-operations.md#source-handling)。
- 新增翻译首选仓库外 `DEEPSEEK_API_KEY_FILE` 私密文件，兼容现有 `DEEPSEEK_API_KEY` 环境变量；有密钥仍须满足开关、范围和金额门禁。配置缺失时不调用服务，也不能视为全库简介已补齐。

## 来源预检

| 状态 | 含义 |
| --- | --- |
| 未识别安装源 | 尚未解析到与项目匹配的来源，不代表无法安装 |
| 已识别安装源 | 目标语法与项目归属可以解析，尚未远程验证 |
| 来源已预检 | 清单元数据中的来源身份、Bundle 声明与精确版本/commit 已核对 |
| 来源预检未通过 | 本次来源结构或身份校验未通过，可重新预检 |
| 来源暂未确认 | 网络、限流或资料缺失等原因导致未完成检查 |
| 来源需重新预检 | 记录已过期或时间无效，需要再次核对 |
| 安装后需配置 | 作者声明有配置要求；即使来源已预检仍保留该提示 |

预检不执行仓库代码、不安装包，也不验证发布归档。缓存绑定仓库、目标、包名和子目录；任一改变即失效，成功与未通过记录最多保留七天，暂未确认结果一天后重试。实际安装仍走原有精确来源预检与确认流程。

`INSTALL_ASSESSMENT_BATCH_SIZE` 控制每次同步的来源检查量，默认 100，范围 0–2000；设为 0 只复用有效结果。本批检查优先重点榜单，再按 Stars 排序。Skill 文件检查仍由原有 Skill 安装预检负责。

## 本地修复与上线顺序

先保存一份完整的 `rankings.json`，输出到单独目录：

```sh
npm run catalog:repair -- /path/to/original/rankings.json /path/to/repaired --verify-sources
```

该命令生成榜单、manifest、分页、搜索索引、`repair-report.json`、`description-jobs.json` 与 `install-assessments.json`。保留原排名、Stars、增长指标与数据时间。省略 `--verify-sources` 可重建产物并复用已保存的预检结果。输出目录不能覆盖原输入文件。

本地快照是复核候选，不会修改线上数据库。当前受控日常流程分为采集、发布与验收，按来源规则应用固定复核内容、导入数据库并发布一致快照；手动 `npm run update:once` 仍可用，但不继承受控调度的锁、阶段恢复和容量预检，不与日常作业并发运行。发布前确认运行配置、待复核数量与候选数据差异。普通服务端文案修改只需重新发布服务端数据；仅不兼容数据契约、插件功能/UI 或宿主兼容改动才评估插件发版，不批量修改被收录的第三方插件。

## 每日更新与本地批处理共用规则

`scheduler-entry.ts` 在 `DSH_AUTOMATION_ENABLED=1` 时进入受控调度：独立执行 `collect`、`db:sync` 与发布验收，阶段状态持久化并跳过已完成工作；独立 watchdog 巡检，免费每周发现只在当日日更验收后分段运行，不直接发布。关闭开关时保留旧 `update:once`（`collect` → `db:sync`）流程。详见 [日常运维](./daily-operations.md)。每日中文、每日分类和 `catalog:enrich` 共用 `content-source.ts` 的来源身份、资料门槛、显式暂停、子包范围检查及退避时间。未完成字段遇到 `review-required` 或 `missing-source` 时，不调用模型，也不从旧派生缓存补齐；完整同源市场数据中已有的有效内容和匹配复核规则仍保留。

来源身份包含仓库、名称、类型、原描述、README、Topics、所选包名与子目录，并绑定内容策略。每日重新组装条目时，先核对完整的上次市场源，再迁移已有中文与有效分类，避免冷缓存导致整库重做。没有来源哈希的旧中文缓存、只有不完整哈希的旧分类缓存不能直接当成同源证据。Stars、排名、Topics 等元数据变化不能单独获得付费资格；包、类型或选定路径改变先复核身份。功能资料变化后依照当前来源证据判断复用、待审或重新生成；旧文的日期展示与模型作业资格分开处理，独立的新编辑和当前匹配复核规则优先。

门禁关闭时不发起模型请求，也不消耗任务尝试次数；同源有效中文和分类仍可离线保留，目录和榜单继续更新。日常授权只覆盖获准的简介与分类任务，标签归一化、整合包介绍、试跑及手动补齐不能借用日常范围。请求默认值统一保存在 `collector/src/model-defaults.ts`：Flash、显式关闭思考、输出上限 256 tokens、并发 3、超时 45 秒。每日每个作业每轮只发起一次请求；通用简介及标签请求默认至多一次额外重试，仍须单独满足获准范围与预算。标签每轮最多处理 20 个候选标签、输出 6 组映射；无效响应不应用，也不记录提供方原文。每日 300 个中文作业、200 个分类作业仅是额外数量上限，门禁关闭时实际派发为 0。两榜与 Skills 的优先简介共用中文请求上限及金额账本，不因范围开关增加总预算。每日持久化失败仍按 1、2、4、7 天退避，但底层不重发已完成或未知计费请求，明确已结算的可重试失败最多追加一次。

`description-jobs.json` 与新增 `category-jobs.json` 位于采集数据目录，保存资料哈希、完成结果、尝试次数和下次时间。请求前保存尝试，成功后立即保存内容；后续缓存或导出中断时可恢复已完成结果。写盘失败会停止派发，并等待在途请求收尾。作业状态文件损坏时停止更新，不静默清空后重新调用模型。

本地冻结批次继续使用独立的 `enrichment-state.json` 与日志，不会被每日调度自动读取。已验收的冻结内容通过 `catalog:merge` 进入市场源，再由每日完整来源迁移保留。`env.txt` 不是服务器自动配置入口；密钥与预算优先使用仓库外私密文件，其他部署配置使用既有运行环境变量或未提交的 `.env`。文档中的命令说明不代表授权新增模型请求、部署或启动后台任务。


## 批量补齐与断点续跑

先检查剩余工作，不请求模型、不写文件：

```sh
npm run catalog:enrich -- /path/to/frozen/rankings.json /path/to/enrichment --dry-run
```

当前版本支持 `--dry-run`、`--limit 0`，以及所选种类已无待办时的离线操作；未配置已确认名单与预算时，有待派发任务的批处理命令会在写入状态和领取任务前明确拒绝。以下参数说明保留供后续恢复时参考，配置 Key 不会恢复请求。每条简介和每次分类各算一个模型请求，`--limit` 是本批请求上限；默认 100，默认并发 3，手动批处理参数上限 256，但底层全项目真实在途上限仍为 3。可用 `--kind description` 只补中文或 `--kind categories` 只做分类，默认 `all`。资料不足和失败项目独立记录，失败退避期间优先处理其他项目：

```sh
npm run catalog:enrich -- /path/to/frozen/rankings.json /path/to/enrichment --limit 100 --concurrency 3
```

默认模型 ID 为 `deepseek-flash`，对应 2026-09-10 发布的 V4.1 Flash；2026-09-11 已核对[官方更新说明](https://api-docs.deepseek.com/updates/)。请求显式关闭思考，代码不自动升级模型。长尾整批继续暂停；恢复独立批次前须离线确定受影响条目，确认样本与整批范围、实际模型、价格及共享金额预算，不能使用日常授权代替批次授权；`--model` 参数或 Key 不会解除门禁。子包没有自己的 README 时不回退到根项目摘要；模型和兜底规则也不使用根仓库 description 代表子包功能。冻结资料未标明选中子包/路径、或仍指向 DSH 根运行时包时，先隔离为待复核。人工发现收录身份不清的条目通过 `collector/config/editorial-holds.json` 绑定原始资料与安装证据，标为 `review-required`；资料变化后再重新判断生成资格。

`complete` 表示该生成任务有结构有效的结果，不代表人工逐条验收或第三方功能验证。全库生成产物应先作为独立候选复核，分类结果保留 `deepseek` 或 `manual` 来源，简介作业保留资料哈希与策略版本。

重复相同命令复用已完成结果。原始功能资料或身份变化先确定影响及处理方式；仅模型、prompt 或策略版本变化不能作为全库失效或付费重跑授权。版本迁移须先离线列出受影响范围，保护仍有效的结果和固定复核内容，再按批准的样本与批次执行；本地计划或检查点重组也不等于获准消费。`enrichment-state.json` 保存作业检查点，`enrichment-journal.jsonl` 逐次保存请求开始和完成结果，`enrichment-progress.json` 保存统计，`snapshot/` 保存本批生成的一致快照。中断后回放日志，只容忍日志末尾不完整行；每 100 个事件与结束时先写检查点，再清理日志。保持原输入文件不变且置于输出目录之外。只统计或 `--limit 0` 本地重建不需要模型密钥；不自动提交、部署或启动后台计划任务。

## 将内容带回常规采集数据

验收候选后，先将内容合并到独立的市场数据副本，避免下次 SQLite 同步重新使用旧介绍：

```sh
npm run catalog:merge -- /path/to/plugins.json /path/to/enrichment/snapshot/rankings.json /path/to/merged-plugins.json --dry-run
npm run catalog:merge -- /path/to/plugins.json /path/to/enrichment/snapshot/rankings.json /path/to/merged-plugins.json
```

该命令逐条核对仓库、类型、名称、原描述、README、Topics 与所选包名/路径，只合入有效中文、标签和当前策略的固定复核/模型分类。当前固定复核规则优先；已有有效中文、标签与当前有效的固定分类受保护，旧模型候选不能覆盖后来编辑。来源已变化的条目跳过；两份输入、排名、Stars、安装源和其他采集字段保持不变。合并副本可能仍有旧来源中的无效中文与旧策略分类，不能直接复制为公开数据。检查统计后，必须让 `db:sync` 通过 `SOURCE_DATA_PATH` 读取副本，执行每日分类计划及中文兜底，再使用其生成的公开快照；明确撤回的固定内容优先于旧结果保护。此步骤只创建本地文件，不自行更新服务器或发布。

这些密钥用于目录维护：GitHub 凭证用于读取仓库并获得较高请求配额，DeepSeek Key 用于获准的模型任务。固定复核不以模型 Key 为前提，安装 Top100 插件也不要求用户为了浏览目录提供它们。密钥通过既有私密文件或环境配置使用，不作为命令行参数或报告内容；模型预算配置与密钥分开保存在仓库外。

### 定向复核的每日保留

已迁移的来源在截断前去除开头中英语言导航，再生成摘要；其他来源继续使用原摘要规则，不因这次修复全库失效。已确认的包目标仍需在当前来源验证，缓存或历史恢复不能选回旧包。

少数没有独立README的包通过 `collector/config/reviewed-function-evidence.json` 绑定明确源码文件的SHA256。每日读取同一当前commit的这些文件；匹配后保留复核结果，确认变化或缺失则暂停旧简介和分类，网络失败只允许保留同仓库、同身份且已有有效核验标记的旧来源。它是限定文件的静态证据，不代表安装运行成功；即使只改manifest版本，也需重新复核。

安装命令缓存有精确README时本地重解析；已确认从禁止示例误提取的命令，在缺源恢复时也不得复活。合法本地tgz示例只作展示，不等于存在公开可用安装源。
