排名方法

榜单、分类与 DSH 插件。

本页目录 产品与榜单 DSH 插件 仓库发现 收录规则 排行算法 数据发布

01 · Overview

三个榜单与分类筛选

dsh-top100 帮助你发现 DSH 插件、比较项目热度并找到安装入口。排名单位是 GitHub 仓库；Skills 单独展示。收录检查确认项目与 DSH 的关联证据，不代表已安装验证、通过能力评测或安全审计。

Composite signal

Top 100

综合近7日增长和累计 Stars，衡量支持 DSH 的仓库关注度。

Recent momentum

新锐榜

按近3日仓库净增长与原有规模计算涨势，至少净增3星；不限制项目年龄。

All verified

总榜

展示全部活跃且符合收录规则的插件仓库，按当前 GitHub Stars 总数降序排列。

README semantics

分类筛选

在综合热度、涨势或 Stars 排序下，按用途进一步筛选；同一插件可以属于多个分类。

README 智能分类

DeepSeek 根据 README、描述和 topics 选择一个主分类，再补充一至两个有明确依据的相关分类。 同一项目可能属于多个分类，所以分类数量相加可能大于项目总数。模型不可用时，使用基于项目资料的规则分类。

02 · DSH Plugin

排行榜也可以直接进入 DSH

安装 dsh-top100 后，可以在 DSH 设置页浏览、搜索榜单，核对来源、版本和安装脚本后确认安装，并在「已安装」中管理插件。

更新默认保留原频道、版本范围或分支，已是最新时不会重复安装。批量更新最多检查 200 项，失败和无需更新的项目单独说明，可更新项目统一确认。

Skills 使用独立目录，并由所有 Profile 共用。替换或卸载前会完整备份原目录、本地修改和新增文件，操作结果显示备份路径。

插件与网站共用线上榜单。安装来源可以解析，不代表已经实际安装验证；运行前仍需核对项目说明、宿主版本和所需权限。

查看安装、更新与备份指南 →

安装包还内置 recommend-dsh-plugins Skill，并注册只读的 dsh_top100_search 搜索工具。当用户在 DSH 对话中询问“该装哪个插件”或描述所需能力时， DSH 会加载该 Skill，从实时 Top100 插件市场检索并给出有榜单数据依据的推荐。

03 · Discovery

如何尽可能完整地发现仓库

系统从多个公开来源发现候选项目，再按同一套收录规则筛选。自动发现可能有遗漏，收录范围以当日快照为准。

多来源候选 结构验证 README 分类 SQLite 快照 公开榜单 JSON
  1. Repository Search：搜索 DSH 名称、描述、README 与 topics。
  2. Code Search：寻找 SKILL.md、DSH/Cordis 配置和依赖等强结构标记。
  3. 生态来源：补充 npm、Awesome 列表、相关组织仓库、历史目录和用户提交。
  4. 递归分片：每周完整发现按创建时间切分，必要时再按 Stars 和仓库大小切分，避免 GitHub 单次搜索 1,000 条结果上限造成静默遗漏。
  5. 稳定去重：优先使用 GitHub repository ID；同一仓库从多个来源命中时合并并保留全部来源证据。

04 · Verification

什么仓库可以入榜

名称、标签和关键词用于发现候选项目，不能单独证明兼容性。候选仓库还需提供 DSH 插件、Skill、Bundle 或 Cordis 集成等结构证据；这些检查不等同于实际运行测试。

检查 通过条件 处理方式
仓库状态 公开、未归档、不是 fork 不符合则排除
结构证据 Skill 文件、Cordis/DSH 配置、package 依赖或可解析插件目录 至少命中一种强证据
数据完整性 仓库 ID、名称、Stars、更新时间和来源可读取 失败保留上次有效数据
社区提交 与自动发现候选使用相同验证规则 提交不等于直接入榜

05 · Ranking

Top 100 如何计算

两榜衡量所属 GitHub 仓库的关注度，不代表具体插件的使用量或质量。 热度榜显示热度分，新锐榜显示0～100分的新锐指数，总榜显示仓库 Stars。

热度分 = 60 × √G7 / (√G7 + √20) + 40 × √S / (√S + √100)
R = G3 / √(B3 + 50)
新锐指数 = 100 × √R / (√R + √5)

固定换算不改变原始排序，不按每天第一名归一化。原始得分5、20、45分别对应50、66.67、75分；100为上限，不要求第一名达到100分。

S 为当前 Stars，G7、G3 为近7日、3日净增长（计分时负增长取0），B3 为3日前 Stars。 热度榜要求至少10星；新锐榜要求3日净增至少3星。两榜最多100项，数据不足不凑数。 中文简介、资料完整度和提交频率不加分。热度同分按周增、Stars、仓库名称排序；涨势同分按3日增量、Stars、仓库名称排序。

增长必须有对应日期的成功观测，实际间隔与目标窗口相差不超过6小时。 刷新失败保留旧观测时间，缺日不冒充零增长。增长保留负数，未知显示数据不足。

过渡期可使用2026年9月17日及以前对应日期的历史快照，日增、3日和7日增长按对应日期快照计算，过渡期结果属于估算。 旧快照可能包含延迟刷新，不能当作精确增长。准确观测齐备后优先替换；日增历史快照过渡最晚至9月18日，新锐榜估算窗口最晚至9月20日，热榜最晚至9月24日，后续缺数据不会延长过渡。

06 · Persistence

数据何时更新

计划在北京时间每天 06:00 开始更新，每周日进行更完整的仓库发现。采集需要时间，页面上显示的快照时间才是本次数据的实际更新时间。

为什么数据可能暂时没有变化

GitHub 请求限制、网络异常或采集失败可能延迟更新。新快照生成成功后才发布；更新未完成时继续提供上次有效数据。

简介与分类如何更新

简介和分类依据公开项目资料整理。缺少可用的中文简介时保留项目原文；项目资料发生变化后，旧的人工整理内容可能失效并等待重新核对。
