装好了，如何安装其他插件？
  1. 在 DSH 的「设置 → 插件排行」中搜索需要的插件。
  2. 点击「安装」，核对来源、版本及安装脚本，再确认。
  3. 按作者说明完成额外配置；提示重启时，按重启说明操作。
  4. 到「已安装」核对项目，再打开插件功能，确认可以使用。

只有「查看项目」？请按作者说明安装。官网的「复制安装命令」需要到终端执行。

「已安装」表示文件或配置已写入，运行效果还需实际验证。来源校验不等于安全审核。

如何更新插件和保留 Skill 修改？

进入「设置 → 插件排行 → 已安装」检查更新。当前版本已最新时不会重复安装；检查失败可刷新后重试。批量更新单次最多检查 200 项，逐项说明无需更新或失败的原因，可更新项目统一确认后执行。

默认沿用原 npm 频道、版本范围或 GitHub 分支。只有明确选择「切换到最新版」才改用最新发布频道或默认分支。旧安装如提示「固定当前版本并保留频道」，请先核对并确认整理；这一步保留当前版本，避免更新其他插件时顺带升级。

Top100 自身通过上面的安装命令升级，沿用原来的 DSH 版本、命令前缀和 Profile。完成后按重启说明重启，再检查「已安装」中的版本。

Skill 由所有 Profile 共用。在 Skills 目录点击「安装 / 更新 Skill」核对来源；替换或卸载前会完整备份原目录，包括本地修改和新增文件。操作结果显示备份路径，恢复前先核对当前目录中的新修改。

复杂 workspace 的旧频道整理可能需要手动维护；失败、取消或外部修改时请按页面提示检查备份。具体范围见更新与备份说明。

遇到问题？查看安装帮助
怎样重启 DSH？

回到正在运行 DSH 的终端，按 Ctrl+C 停止，再执行原来的启动命令。打开终端打印的完整本地网址，并保持终端运行。后台服务用户沿用原有服务管理方式；仅刷新网页不能代替重启。

提示找不到 node、npm 或 pnpm

缺少 Node.js 或 npm 时，前往Node.js 官方下载页。只有 pnpm 缺失时，查看pnpm 安装帮助。安装后关闭并重新打开终端，再检查版本。出现 pnpm not found on PATH 表示 DSH 没有找到 pnpm，尚未完成插件安装。

安装后找不到「插件排行」，或榜单无法加载
  • 运行所选路径中的安装结果检查命令，确认插件已加入 web profile。
  • 确认安装和启动使用了同一个 DSH 版本、相同命令前缀和配置目录。
  • 若安装时 DSH 已在运行，先重启 DSH，再刷新浏览器。
  • 入口已出现但榜单无法加载时，检查是否能访问官网榜单，再重试加载；这与插件没有安装是不同的问题。
新版本被发布等待期拦截

仅当出现 ERR_PNPM_NO_MATURE_MATCHING_VERSION 或 minimumReleaseAge 报错时，才需要处理。不同 pnpm 版本和配置行为不同；可以等满报错要求的发布时间后重试。

需要立即安装此版本时，在当前 Web Profile 的 pnpm-workspace.yaml 中合并以下精确版本例外，保留其他配置和已有条目：

minimumReleaseAgeExclude:
  - '@dsheval/dsh-top100-plugin@1.3.10'

默认文件在用户主目录的 .dsh/profiles/web/pnpm-workspace.yaml；设置了 DSH_HOME 时，在该目录的 profiles/web/ 下。对应路径中的安装检查命令会准备 Profile；若文件仍不存在，请在该 Profile 目录创建它。

保存后，将你刚才实际执行的安装命令中的 add 改为 add -w，其余部分保持不变，再运行一次。

该例外只适用于这个版本。报错若指向其他包，需单独核对，不要关闭全部依赖的等待期。

npx 长时间没有输出

先确认终端是否在等待输入 y。首次下载可能需要几分钟；已有进度时请继续等待。持续无输出时，按 Ctrl+C 停止，检查网络，用你当前的命令前缀运行 --version 检查 DSH。新用户对应命令为 npx @deepseek-ai/dsh@0.1.5-rc.2 --version。

版本检查也无法完成时，问题发生在 DSH 下载或启动阶段。请保留报错并查看 DSH 官方安装说明。不要单独添加 --legacy-peer-deps，以免漏装运行时依赖。
